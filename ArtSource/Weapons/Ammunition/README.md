Six local Pixal3D models for the game's cartoon weapons. The complete rounds are standalone props; the flying projectiles replace the existing placeholder meshes in the already-referenced projectile prefabs.

## Editing in Unity

- Drag a saved ammunition prefab into a scene and edit its Transform or MeshRenderer material normally. These are art props; no ammo pickup or inventory behavior is added.
- Complete rounds stand on their base on local +Y, in metres. Authored heights are 7 cm for the shell, 5.7 cm for the rifle round and 3 cm for the pistol round. These are game art proportions rather than manufacturing specifications.
- Projectile meshes point along local +Z and are centred on their origin. Their saved prefab scale previews the weapon's normal visual size. `WeaponProjectileVisual.Launch` continues to apply the weapon's Inspector `Bullet Size` setting.
- The shotgun's existing serialized visual size and code default now use equal axes so the generated pellet remains round. Damage, ammunition counts, spread, speed and other gameplay settings are preserved.
- `WeaponProjectileVisual` has a serialized **Tint Mesh With Weapon Colour** checkbox. It defaults to the previous behavior for existing components, and is disabled on these three textured projectile prefabs. The copper and gunmetal textures keep their colours while existing trails still use each weapon's colour.
- The three existing projectile prefab GUIDs, root component file IDs, trail settings and gameplay references are preserved. Ejected-casing effects are separate existing assets and were not replaced with loaded cartridges.
- Meshes are saved under `Assets/_Project/Models/Weapons/Ammunition/`; URP Lit materials under `Assets/_Project/Materials/Weapons/Ammunition/`; textures under `Assets/_Project/Textures/Weapons/Ammunition/`.
- Each material has a generated base-colour atlas and a packed metallic/occlusion/smoothness atlas. Texture sizes are 512 for ammunition and 256 for projectiles, with mipmaps.

All prefabs and references are saved assets. No runtime hierarchy builder, import-time generator or automatic prefab rewrite was added.

## Source and generation

The reference images were made with built-in **ImageGen**, not an API fallback. The complete prompt set and original generated-image paths are recorded in [ReferencePrompts.json](ReferencePrompts.json) and [RevisionPrompts.json](RevisionPrompts.json). Final references are in `References/`; editable GLB source meshes with their embedded original PBR textures are in `Generated/`.

The geometry was generated by the installed native Pixal3D INT8 model in local ComfyUI on the RTX 3060 Ti. There are no hosted-generation API nodes or per-generation credits. `GenerationJobs.json` records the initial run; `RevisionJobs.json` records the corrected foreground-mask pass. [SourceSelection.json](SourceSelection.json) records the reviewed candidate chosen for each asset: the corrected pass for five models, and the cleaner first pistol-cartridge candidate. The saved `_v2.json` graphs are the corrected workflows for future generation.

The import step keeps generated topology and UVs, aligns each object, corrects cartridge cross-section proportions, removes small disconnected fragments, converts units/axes and packs texture channels for Unity. The raw GLBs are retained so those art decisions can be revisited. Foreground masking uses the official background-removal path; the transparent-alpha bypass includes the required inverse-mask conversion.

Explicit authoring helpers, run manually from the repository root with `C:/Users/Jaden/AI/Pixal3D/venv/Scripts/python.exe`:

- `Tools/prepare_pixal_ammunition.py`: prepares original references and local generation graphs.
- `Tools/revise_pixal_ammunition.py`: applies the revised references and writes the final corrected graphs.
- `Tools/import_pixal_ammunition.py`: imports completed GLBs into saved Unity meshes, textures and prefabs. Existing material assets and complete-ammunition prefab Inspector settings are preserved on rerun.
- `Tools/prepare_ammunition_unity_validation.py`: makes an isolated temporary Unity project with just the required assets and scripts; `--reuse` refreshes that task-owned project.
- `Tools/Unity/ValidatePixalAmmunition.cs`: explicit Unity batch validation and three-angle render capture.
- `Tools/preview_pixal_ammunition.py`: assembles the preview sheets from Unity's captured images.

## Validation

The final machine-readable result is [UnityValidation/UnityValidation.json](UnityValidation/UnityValidation.json). Checks cover native Unity import, mesh/material/texture references, finite geometry, UVs/normals, triangle budgets, preserved projectile components and trails, actual `Launch` behavior, +Z firing orientation and a round shotgun pellet.

The validation renders use neutral Unity preview lighting and the generated base-colour textures. The production prefabs retain their URP Lit materials and generated metallic/occlusion/smoothness maps. The main game's open scene is not modified by the validation project.

The source images are generated for this project. The locally installed Pixal3D model's MIT license and dependency notices remain in `C:/Users/Jaden/AI/Pixal3D/licenses/`.
